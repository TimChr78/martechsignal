Notifo Review

Self-hosted multi-channel notification service for email, SMS, and web push

Email Marketing · Open Source · OPEN SOURCE

Overview

Notifo is an open-source notification service that unifies email, SMS, web push, and mobile push behind one API with a management UI for templates, users, subscriptions, and projects. Built by the Squidex team, it targets product and marketing teams that send transactional and lifecycle messages: signup confirmations, alerts, digests, and re-engagement pings. The feature set is practitioner-grade: MJML and Liquid email templates, a REST API with OpenAPI documentation, message queues and retry mechanisms per channel, read and confirmed tracking, and a JavaScript plugin for in-app notification overlays. Provider support is concrete rather than abstract: Amazon SES for email, Firebase for mobile push, MessageBird for SMS, and custom-built web push, with sockets for real-time web delivery. Docker images are published and self-hosting is the intended mode. With 878 stars the community is modest, and the last significant activity should be checked before adoption, since notification infrastructure is the kind of thing you want actively maintained. For teams already running Squidex CMS, it is the natural companion; for everyone else it competes with Courier, Knock, or plain provider APIs.

Hands-on notes

Notifuse Squidex-style multi-channel notifications - the project gives you one API surface over email, SMS, and push providers, self-hosted. Configuration centers on provider templates and channel fallbacks rather than campaign design. That focus is its identity: infrastructure, not marketing tooling.

Choose it to unify scattered provider calls behind one internal service. Newsletter marketing belongs in a different category of tool entirely.

Verdict

Good unified-notifications middleware for developers; not a campaign sender.
